# GOAL.md template — Node.js CLI tool

Read this file when generating `goals/<slug>/GOAL.md`. Substitute every `{{...}}` placeholder with values confirmed in Step 3 of the skill flow. Do not delete sections that don't apply — write `Not applicable.` plus a one-line reason instead.

The six AI-agent patterns (--json, stdout/stderr separation, TTY detection, exit codes, structured errors, --dry-run) are baked into Sections 7, 8, and 9 as default rules. They appear in every generated GOAL.md. If a pattern doesn't apply (e.g., --dry-run for a read-only tool), note the exception explicitly rather than silently removing the rule.

## 9. Error Handling

/goal must handle:

- Missing or invalid configuration (env vars, config files)
- Invalid command-line arguments
- File not found (when input is a file path)
- Network / API failures (when calling external services)
- Permission errors (file system, API auth)
- {{Edge case from spec}}

Expected behavior:

- Errors produce a message to stderr and exit with code 1.
- When `--json` is active, errors use structured format on stderr:
  ```json
  { "error": "CODE", "message": "...", "suggestion": "..." }
  ```
- No stack traces in production output unless `--debug` flag or `DEBUG` env var is set.
- Individual non-fatal failures produce warnings to stderr but don't abort the main operation (when applicable).

{{When OAuth is confirmed, add these error cases to the list above:}}

- Token exchange failure (provider returns error) → stderr + exit 1
- OAuth redirect server timeout (user didn't approve within 120s) → stderr + exit 1
- Missing or invalid ENCRYPTION_KEY (Tier 2) → structured error with suggestion to generate one
- Expired or revoked refresh token → stderr + suggestion to re-run `auth login`
- Network failure during token refresh → stderr + exit 1, suggest `auth status`
